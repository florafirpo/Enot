## Supuestos y decisiones
- **No escribir el set en esta corrida.** Crear `data/eval/test/` es irreversible (hook, ADR-0007), y la paráfrasis
  necesita la clave de Flora y tiene que decidirse antes. Quedó como decisión pendiente.
- **Infactible = demostrable por código** (ADR-0016). El ejemplo del PRD "8 bodegas entre Chablis y el Mâconnais"
  se reformuló: con auto y 9 h de jornada no es demostrablemente imposible.
- **Cuotas múltiplos de 5**, para que 60/40 y 20% sean exactos por escenario. Infactibles con 20, para medir sobre 8
  casos de test y no sobre 4.
- **Comunas de referencia por zona** con coordenadas aproximadas del centro de cada comuna. Es geografía pública,
  no datos de bodegas. El certificado usa el par más cercano entre las dos zonas, así es conservador.
- **Etiqueta de zona = nombre canónico** ("Chablis y Grand Auxerrois") aunque el texto diga "Chablis". El filtro de
  retrieval coincide por palabras, así que las dos formas encuentran las mismas bodegas.
- **Bici y a pie, factibles, siempre con una sola zona**, para no meter infactibles sin etiquetar.
- **Visita mínima 30 min**, como cota inferior.
- **Las preferencias blandas no son anclas.** Una paráfrasis las puede reformular; la etiqueta queda fija.
- El hook de Bash bloqueó un `python - <<EOF` que editaba README y CHANGELOG, porque el texto mencionaba la ruta del
  set y contenía `>`. Es un falso positivo de la regex (no se tocaba `data/eval/test/`). No lo esquivé por Bash:
  esos archivos se editaron con la herramienta de edición, que es el camino normal.

## Para la defensa
- **Qué hace cada pieza nueva:**
  - El generador arma pedidos de turista desde plantillas, con la etiqueta como el mismo `PerfilViaje` que extrae
    el agente.
  - El certificado prueba con código que un pedido infactible es imposible.
  - La partición y la muestra son estratificadas y salen de una semilla fija.
  - La planilla de revisión mide la tasa de error del generador.
- **Por qué así (ADR-0016):**
  - Si el LLM generara consulta y etiqueta, no habría garantía de que la etiqueta sea correcta y el benchmark
    mediría al generador.
  - Si los infactibles se definieran con el corpus real, la etiqueta cambiaría con cada corrida de la extracción.
  - La paráfrasis está, pero controlada por anclas: el LLM solo toca la redacción.
- **Pregunta posible:** "¿Cómo saben que un pedido 'infactible' de verdad lo es, y que no castigan al agente por
  resolverlo?" → Solo se etiqueta infactible lo que `certificado_infactible` demuestra con las mismas constantes que
  usa el verificador, y un test exige que coincidan en los 100 casos. Lo factible no tiene garantía con el corpus
  real; eso lo reporta el 007 aparte.
- **Pregunta posible:** "¿Las consultas sintéticas se parecen a pedidos reales?" → Es la limitación conocida (ADR-0007).
  Se mitiga con varias plantillas por escenario, la paráfrasis opcional y la revisión manual del 20%, que da una
  tasa de error reportable.
